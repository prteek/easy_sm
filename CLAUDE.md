This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**easy_sm** is a Python CLI (Python >=3.13, built on Typer) for prototyping SageMaker training, jobs and endpoints locally with Docker, then running the same commands in the cloud.

**Version 2 (2.0.0) is a complete rewrite** with no backward compatibility with 1.x; 1.x lives only in git history and on PyPI. The design and its reasons are in `decisions.md` (section *CLI redesign*); the build order is its *Build order for the rewrite* bullet. Only describe and document what exists in the code now.

### Design principles
- **hf-style CLI**: commands grouped by resource then action (`easy_sm jobs ls`), the main object as a positional argument, sensible defaults, `--local` to run the same command in local Docker
- **Settings lookup**: flag → environment variable → `easy_sm.toml` → built-in default
- **Pipe-friendly**: stdout carries only data (names, paths, tables); messages, logs and errors go to stderr
- **Minimal**: runtime dependencies are only `typer` and `boto3`; no SageMaker SDK, no Docker SDK

### Documentation files
- `.github/README.md`: user guide and PyPI page. Minimal: two example workflows (train/deploy, run a script), command table, hf credits
- `easy_sm/skill.md`: guide for coding agents, written by `easy_sm skill`. A test fails if a command is missing from it
- `diagrams/`: flows and call maps. When a command or check changes, update `make_diagrams.py` and run `python3 diagrams/make_diagrams.py diagrams`
- `summary.md`, `decisions.md`, `todolist.txt`: project docs (see `/project-docs`)
- When adding a command: update `skill.md`, the README command table and the diagrams

### Config (`easy_sm/config.py`)
- Every known setting is listed in `SETTINGS` as `"section.name": Setting(type, env=..., default=...)`. Adding a setting = one line there (and a commented line in `scaffold/easy_sm.toml`)
- `load(path)` rejects retired keys with a hint (`RETIRED`, e.g. `aws.profile`), unknown keys, wrong types, missing/invalid `app_name`, non-string `run.env` values. Raises `ConfigError`
- `Config.resolve(key, flag)` returns `(value, source)`; `Config.get(key, flag)` returns the value. `env` is a parameter so tests pass a dict instead of patching `os.environ`
- `app_name`: lowercase letters, digits, single hyphens, max 32 chars (it becomes the Docker image, ECR repo and SageMaker job/endpoint name prefix)
- Env overrides: `AWS_REGION`, `SAGEMAKER_ROLE`. With no region set, boto3's own (`AWS_DEFAULT_REGION`, `~/.aws`) is used
- **No profile setting**: credentials come from boto3's default chain exactly like the AWS CLI (env keys, `AWS_PROFILE`, OIDC, instance role). `easy_sm env` shows the account and credential source actually used

## Code Style

- Type hints on all parameters and return values; f-strings
- Typer options with `Annotated[..., typer.Option(..., help=...)]`; always help text
- Errors: raise `ConfigError` (or a specific exception) in library code; the CLI layer prints the message to **stderr** with `typer.echo(..., err=True)` and exits 1
- Imports: standard library → third-party → local, alphabetical
- **Keep AWS and Docker calls thin**: pure functions build the request (boto3 call kwargs, `docker` argv, image hash); the line that sends it does nothing else. Test the pure functions

## Testing

- Plain pytest, **no mocks of SageMaker, boto3 or Docker** (decision 2026-11-03). Tests exist to explain behaviour: one idea per test, named as a sentence
- Use `tmp_path` and `monkeypatch.chdir`; pass `env={...}` dicts rather than patching the environment
- AWS behaviour is checked by running the workflow against a real account, listed in `todolist.txt`

## CI and release

- **test.yml**: on push/PR to main: `pip install -e . --group dev`, then pytest, mypy, `ruff check easy_sm/ tests/`
- **publish.yml**: on `v*` tags only: `python -m build` → PyPI via **Trusted Publishing** (environment `pypi`, bound to `prteek/easy_sm` + `publish.yml`; renaming either breaks publishing) → GitHub release. Least-privilege job permissions, default `permissions: {}`
- **Actions are pinned to commit SHAs** with a `# vX.Y.Z` comment; Dependabot bumps them weekly. Pin new actions the same way (`git ls-remote https://github.com/OWNER/REPO refs/tags/vX.Y.Z^{}`)
- **Release**: bump `easy_sm/__init__.py`, commit to main, wait for CI green, then `git tag vX.Y.Z && git push origin vX.Y.Z`. A PyPI version can't be re-uploaded, so tag only after CI passes
